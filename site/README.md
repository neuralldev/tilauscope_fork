# tilauscope.org

The public front page. A static site with no build step: what is in this
directory is what gets served.

```
index.html            the page
site.css              tokens, then components — no inline styles anywhere
site.js               the hero curve and the phase rail — no inline scripts
hero.png              the hero photograph
fonts/                Fraunces and JetBrains Mono, subset to Latin, WOFF
fonts/OFL-*.txt       their licences, which must travel with them
favicon.svg           generated by tools/shell/gen_app_icons.py
security.txt          served at /.well-known/security.txt — see below
_headers              response headers for Cloudflare Pages and Netlify
_redirects            rewrites /.well-known/security.txt to /security.txt
```

## Why `security.txt` sits at the root, not in `.well-known/`

RFC 9116 puts the file at `/.well-known/security.txt`. Some hosting file
managers won't let you create a directory whose name starts with a dot — the
control panel treats it as hidden and refuses, even though the underlying
filesystem has no such rule. Two ways out:

- **Your host reads `_redirects` or `_headers`** (Cloudflare Pages, Netlify):
  nothing to do, `_redirects` already rewrites the spec path to this file.
  The RFC explicitly allows serving the file from elsewhere via a redirect —
  this isn't a workaround, it's the documented mechanism.
- **Your host doesn't**, or you deploy over plain FTP: upload over an FTP
  client instead of the web file manager if you can — FTP has no objection to
  dot-directories, only some browser-based uploaders do. If that's not an
  option either, ask the host to add a single rewrite rule:
  `/.well-known/security.txt → /security.txt`.

The `hero.png` photograph replaced the earlier Wikimedia Commons placeholder;
no attribution is owed on it.

Every asset is served from this origin. Nothing is fetched from a CDN, a font
host, a badge service or an analytics endpoint, and the page sets no cookies
and writes nothing to storage. That is what lets the Content-Security-Policy
below be written with no escape hatch in it.

## Deploying

Upload the contents of this directory to the web root. There is nothing to
compile, and no server-side code to run.

**Cloudflare Pages / Netlify** read `_headers` as-is. Point the project at
this directory, set the build command to none, and you are done.

**GitHub Pages ignores `_headers`.** It cannot set custom response headers at
all, so the header-only protections — `Strict-Transport-Security`,
`X-Frame-Options`, `frame-ancestors`, `Permissions-Policy` — would silently
not apply. The `<meta http-equiv="Content-Security-Policy">` in `index.html`
still holds, but it is the weaker half. Prefer a host that can set headers.

### nginx

```nginx
server {
    listen 443 ssl http2;
    server_name tilauscope.org;
    root /var/www/tilauscope.org;

    add_header Content-Security-Policy "default-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'; img-src 'self'; style-src 'self'; script-src 'self'; font-src 'self'; connect-src 'none'; manifest-src 'self'; upgrade-insecure-requests" always;
    add_header Strict-Transport-Security "max-age=63072000; includeSubDomains; preload" always;
    # Both of the above assume a working certificate — see "Serving over plain
    # HTTP" below before copying them onto a host that has none.
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-Frame-Options "DENY" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;
    add_header Permissions-Policy "accelerometer=(), autoplay=(), camera=(), display-capture=(), encrypted-media=(), fullscreen=(self), geolocation=(), gyroscope=(), magnetometer=(), microphone=(), midi=(), payment=(), usb=(), xr-spatial-tracking=()" always;
    add_header Cross-Origin-Opener-Policy "same-origin" always;
    add_header Cross-Origin-Resource-Policy "same-origin" always;
    add_header Cross-Origin-Embedder-Policy "require-corp" always;

    location /fonts/ { add_header Cache-Control "public, max-age=31536000, immutable" always; }
    location = /index.html { add_header Cache-Control "public, max-age=0, must-revalidate" always; }

    server_tokens off;
}
```

`add_header` does not inherit into a `location` block that declares its own,
so the two `location` blocks above have to repeat any header they still need,
or be expressed with `map` instead. Kept simple here because caching is the
only thing they change.

### Apache

```apache
Header always set X-Frame-Options "DENY"
Header always set Referrer-Policy "strict-origin-when-cross-origin"
Header always set Cross-Origin-Opener-Policy "same-origin"
Header always set Cross-Origin-Resource-Policy "same-origin"

```

### Serving over plain HTTP

The shipped `.htaccess`, `_headers` and `<meta>` policy omit two directives
that the blocks above include, because the live host has no certificate yet:

| Directive | Why it is out |
|---|---|
| `upgrade-insecure-requests` | Rewrites every subresource request to `https://`. With no certificate the stylesheet, script, fonts and hero image all fail and the page arrives as unstyled markup — the site looks broken while returning 200 on every file. |
| `Strict-Transport-Security` | Ignored by browsers when it arrives over plain HTTP, so it protects nothing today. Its `preload` token is also irreversible in practice: once the domain is on that list, browsers refuse HTTP outright. |

Add both back the day TLS is installed — they are the correct settings for an
HTTPS deployment, and nothing else in this directory needs to change with them.

## What "secured" covers here, and what it does not

Covered:

- **No third-party requests.** Nothing to be tracked by, and nothing that can
  be compromised upstream and served into this page.
- **A policy with no escape hatch.** `default-src 'none'` and an explicit
  allowance per resource type, all `'self'`. No `'unsafe-inline'`, so an
  injected `<script>` or `style` attribute does not execute.
- **`base-uri 'none'`, `form-action 'none'`.** An injected `<base>` cannot
  redirect the relative asset paths, and there is no form to hijack.
- **`frame-ancestors 'none'` and `X-Frame-Options: DENY`.** The page cannot be
  framed, so it cannot be used as the visible layer of a clickjacking overlay.
- **`rel="noopener noreferrer"` on every outbound link,** so an opened tab
  cannot reach back through `window.opener`, and the referrer stays coarse.
- **`nosniff`,** so a mistyped content type cannot turn an asset into a script.
- **HSTS with a two-year max-age.** Note that `preload` is a claim: it means
  nothing until the domain is actually submitted to the preload list, and it
  commits every subdomain of `tilauscope.org` to HTTPS. Drop the token if that
  is not wanted yet.
- **A `security.txt`** telling a finder where to report.

Not covered, because a static page cannot cover it:

- **TLS configuration, DNS and the registrar account.** These are where a site
  like this one actually gets taken over. CAA records and registrar lock are
  worth more here than anything in this directory.
- **Whatever the host adds.** Some platforms inject their own analytics or
  error pages; check the shipped response with `curl -I` after deploying.
- **The download links.** They point at GitHub releases. Integrity of what a
  visitor downloads comes from the macOS notarisation and the Windows
  signature, not from this page.

### Verifying a deploy

```sh
curl -sI http://tilauscope.org | grep -iE 'content-security|strict-transport|x-frame|x-content|referrer|permissions|cross-origin'
```

Then open the page and confirm the browser console is empty: a CSP violation
reports itself there, and the most likely cause of one is an asset that was
added without being added to the policy.

## Follow-ups left open

- `security.txt` points at GitHub's private advisory form, which only works
  once *Private vulnerability reporting* is enabled in the fork's settings.
  Enable it, or drop that line and keep only the issue tracker.
- `Expires` in `security.txt` is set a year out and has to be pushed forward
  before it lapses, otherwise the file is formally invalid.
- No `SECURITY.md` exists in the repository yet, so no `Policy:` line is
  advertised.

## Editing

Copy is written from the reader's side: what the software does for them, not
how it is built. No class, file or method names in the prose.

Headlines are set in Fraunces, instanced from the variable font at optical
size 120, weight 600, SOFT 40 and WONK 1. That last axis swaps in the cocked,
slightly off-axis letterforms, and it is the reason the face is here at all —
at WONK 0 it is an ordinary serif and not worth the bytes. Regenerate with
`fontTools.varLib.instancer`, then subset to Latin and save as WOFF; the
repository has no brotli, so WOFF2 is not available locally.

Colours come
from the application's own palette — Catppuccin Mocha for dark, Latte for
light — and are declared once as custom properties at the top of `site.css`;
nothing below that block hard-codes a colour.

The hero curve is interpolated in `site.js` from a single milestone list, and
the readouts under it are derived from that same list, so the drawing and the
numbers cannot disagree. To change the roast being shown, change the
milestones — not the drawing code.
